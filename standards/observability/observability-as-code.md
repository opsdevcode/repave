# Observability-as-code standard v1.2.0

Governed alerts, monitors, routing, and supporting artifacts generated by the
`observability-as-code-generic` golden path. Dashboard-only repos use
`dashboards-as-code-generic` and `standards/observability/dashboards-as-code.md`.

## Naming

- Repository name: `observability-{organization}-{service_name}` (from blueprint).
- Alert names: PascalCase, prefixed with service context where ambiguous.
- Prometheus rule groups: `{service_name}-alerts`.
- Files under `prometheus/rules/` use kebab-case filenames.

## Required metadata

Every alert rule MUST include:

| Field | Location | Requirement |
| --- | --- | --- |
| `severity` | `labels` | One of `critical`, `warning`, `info` |
| `service` | `labels` | Matches blueprint `service_name` |
| `team` | `labels` | Owning team slug |
| `runbook_url` | `annotations` | HTTPS URL to the runbook |
| `summary` | `annotations` | One-line operator summary |

Grafana dashboards MUST tag `service`, `team`, `org`, `env`, and `managed-by:repave`
(native JSON under `grafana/dashboards/` or Terraform `grafana_dashboard`).

Datadog monitors MUST tag `service`, `team`, `org`, `env`, and `managed-by:repave`.
Monitor messages MUST reference the catalog `notification_target` (for example
`@pagerduty-payments` or a documented routing handle).

## Notification routing

`notification_source` and `notification_target` come from `observability/catalog.json`.
Native Prometheus Alertmanager configs MUST name the receiver after `notification_target`
and include a provider-appropriate stub (`pagerduty_configs`, `slack_configs`, or
`email_configs`). Terraform Datadog monitors MUST include the target in the monitor message.

## SLOs

When `slo_target_percent` is set on generate, the repo includes a starter SLO recording
rule and burn-rate alert stub under `prometheus/rules/` (Prometheus native mode).

## Backends and output modes

| Backend | Native layout | Terraform mode |
| --- | --- | --- |
| `prometheus` | `prometheus/rules/*.yaml`, `prometheus/alertmanager/alertmanager.yaml` | Prometheus community provider (`prometheus_rules.tf`, `alertmanager.tf`) |
| `grafana` | `grafana/dashboards/*.json` | Grafana provider (`dashboard.tf` at repo root) |
| `datadog` | `datadog/monitors/*.json` | Datadog provider (`monitors.tf` at repo root) |
| `otel` | `otel/collector-config.yaml` | Helm provider (`otel_collector.tf` OpenTelemetry Collector chart) |

`output_mode=terraform` emits `versions.tf`, `providers.tf`, `variables.tf`, and backend-specific
resources for **datadog**, **grafana**, **prometheus**, or **otel**.

## Validation

Generated repos run `yamllint`, `promtool check rules`, `amtool check-config` (when
Alertmanager configs exist), `grafana-dashboard`, `datadog-monitor`, `datadog-api-validate`
(when `DD_API_KEY` and `DD_APP_KEY` are set), `terraform-fmt` / `terraform-validate` (when
`.tf` files exist), `opa` (Terraform plan or native JSON/YAML via conftest), `secrets`,
`docs-drift`, and `provenance-drift` gates. Tools skip cleanly when not installed or when no
matching files are present.
