# Observability-as-code standard v1.0.0

Governed dashboards, alerts, and routing artifacts generated by the
`observability-as-code-generic` golden path.

## Naming

- Repository name: `observability-{organization}-{service_name}` (from blueprint).
- Alert names: PascalCase, prefixed with service context where ambiguous.
- Prometheus rule groups: `{service_name}-alerts`.
- Files under `prometheus/rules/` use kebab-case filenames.

## Required metadata

Every alert rule MUST include:

| Field | Location | Requirement |
| --- | --- | --- |
| `severity` | `labels` | One of `critical`, `warning`, `info` |
| `service` | `labels` | Matches blueprint `service_name` |
| `team` | `labels` | Owning team slug |
| `runbook_url` | `annotations` | HTTPS URL to the runbook |
| `summary` | `annotations` | One-line operator summary |

Grafana dashboards MUST tag `service` and `team` (native JSON under `grafana/dashboards/`).

## SLOs

When `slo_target_percent` is set on generate, the repo includes a starter SLO recording
rule and burn-rate alert stub under `prometheus/rules/` (Prometheus native mode).

## Backends and output modes

| Backend | Native layout (v1) | Terraform mode |
| --- | --- | --- |
| `prometheus` | `prometheus/rules/*.yaml` | Follow-up blueprint |
| `grafana` | `grafana/dashboards/*.json` | Follow-up |
| `datadog` | Planned | Datadog provider |
| `otel` | Planned | Collector config |

v1 ships **Prometheus native** alerts; other backends render placeholder README stubs until
expanded.

## Validation

Generated repos run `yamllint`, `promtool check rules` (when installed), `secrets`,
`docs-drift`, and `provenance-drift` gates.
