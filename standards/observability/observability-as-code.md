# Observability-as-code standard v1.3.0

Governed alerts, monitors, routing, and supporting artifacts generated by the
`observability-as-code-generic` golden path (umbrella / legacy multi-backend layout).

## When to use which blueprint

| Need | Blueprint | Standard |
| --- | --- | --- |
| Dashboards only | `dashboards-as-code-generic` | `dashboards-as-code.md` |
| Monitors and alerts only | `monitors-as-code-generic` | `monitors-as-code.md` |
| One repo, multiple backends (Prometheus + Grafana + Datadog + OTel) | `observability-as-code-generic` | this document |

Prefer the focused blueprints for **new** repositories. Keep the umbrella path for
existing multi-backend repos or when you need OTel collector scaffolding in the same
artifact as alerts.

Dashboard-only repos use `dashboards-as-code-generic` and
`standards/observability/dashboards-as-code.md`. Monitor-only repos use
`monitors-as-code-generic` and `standards/observability/monitors-as-code.md`.

## Naming

- Repository name: `observability-{organization}-{service_name}` (from blueprint).
- Alert names: PascalCase, prefixed with service context where ambiguous.
- Prometheus rule groups: `{service_name}-alerts`.
- Files under `prometheus/rules/` use kebab-case filenames.

## Required metadata

Every alert rule MUST include:

| Field | Location | Requirement |
| --- | --- | --- |
| `severity` | `labels` | One of `critical`, `warning`, `info` |
| `service` | `labels` | Matches blueprint `service_name` |
| `team` | `labels` | Owning team slug |
| `runbook_url` | `annotations` | HTTPS URL to the runbook |
| `summary` | `annotations` | One-line operator summary |

Grafana dashboards MUST tag `service`, `team`, `org`, `env`, and `managed-by:repave`
(native JSON under `grafana/dashboards/` or Terraform `grafana_dashboard`).

Datadog monitors MUST tag `service`, `team`, `org`, `env`, and `managed-by:repave`.
Monitor messages MUST reference the catalog `notification_target` (for example
`@pagerduty-payments` or a documented routing handle).

## Notification routing

`notification_source` and `notification_target` come from `observability/catalog.json`.
Native Prometheus Alertmanager configs MUST name the receiver after `notification_target`
and include a provider-appropriate stub (`pagerduty_configs`, `slack_configs`, or
`email_configs`). Terraform Datadog monitors MUST include the target in the monitor message.

## SLOs

When `slo_target_percent` is set on generate, the repo includes a starter SLO recording
rule and burn-rate alert stub under `prometheus/rules/` (Prometheus native mode).

## Backends and output modes

| Backend | Native layout | Terraform mode |
| --- | --- | --- |
| `prometheus` | `prometheus/rules/*.yaml`, `prometheus/alertmanager/alertmanager.yaml` | `prometheus_rules.tf`, `alertmanager.tf` — `null_resource` payloads (rule group + Alertmanager YAML) for GitOps wiring; map to your ruler (Mimir, AMP, Prometheus Operator, etc.) |
| `grafana` | `grafana/dashboards/*.json` | Grafana provider (`dashboard.tf` at repo root) |
| `datadog` | `datadog/monitors/*.json` | Datadog provider (`monitors.tf` at repo root); provider `validate = false` allows `terraform plan` in CI without API keys |
| `otel` | `otel/collector-config.yaml` | Helm provider (`otel_collector.tf` OpenTelemetry Collector chart) |

`output_mode=terraform` emits `versions.tf`, `providers.tf`, `variables.tf`, and backend-specific
resources for **datadog**, **grafana**, **prometheus**, or **otel**. Observability repos vend
`policy/opa/policies/` from the selected [policy pack](../../policy/PACKS.md) and
`tests/fixtures/plan-create-only.json` for Conftest when live plan JSON is unavailable.

## Policy packs

Default generate inputs: `policy_pack_source=repave-observability-pack`,
`policy_profile=observability-default` (see `policy/catalog.json`). Enabled Rego files are
listed in `.repave/policy-selection.json` and copied into `policy/opa/policies/` — not the
full monorepo pack (for example Kubernetes sample rules stay out unless you select them).

| Rule ID | When it applies |
| --- | --- |
| `opa:observability_native` | Conftest on native Datadog/Grafana JSON |
| `opa:observability_prometheus` | Conftest on native Prometheus rules YAML |
| `opa:observability_managed_by` | Terraform plan JSON (Datadog/Grafana resources) |
| `opa:destructive_changes` | Terraform plan JSON (required) |

## Validation

Generated repos run `yamllint`, `promtool check rules`, `amtool check-config` (when
Alertmanager configs exist), `grafana-dashboard`, `datadog-monitor`, `datadog-api-validate`
(when `DD_API_KEY` and `DD_APP_KEY` are set), `terraform-fmt` / `terraform-validate` (when
`.tf` files exist), `opa` (Terraform plan or native JSON/YAML via conftest), `secrets`,
`docs-drift`, and `provenance-drift` gates.

Portal **Dry run preview** and `repave generate --dry-run` set **`require_run`**: blueprint
gates must execute and missing CLIs (Terraform, Conftest, Checkov, etc.) **fail** instead of
skip. Use [Docker Compose](../../deploy/local/README.md) or `deploy/local/install-gate-toolchain.sh`
so dry-run matches CI. Gates may still **skip** when there is nothing to validate (for example
`promtool` with no Prometheus rules in a Datadog-only repo).
